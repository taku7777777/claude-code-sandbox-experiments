# devc-k: タスクごと使い捨て(--rm)インスタンスは秘密を持ち越さない(fail-closed teardown)

## 目的

「コンテナ生成はコストなので**役割ごとにコンテナを共有**し、複数タスクで使い回す」——この案の**代替(推奨形)**
として、**役割はイメージ/権限プロファイルで固定しつつ、インスタンスはタスクごとに使い捨てる**(`--rm`)と、
後続タスクのコンテナに前タスクの秘密が**持ち越されない**ことを示す。長寿命の共有コンテナ(=秘密の集積点)より
fail-closed。

## 前提

- claude 非経由の**機構単離**(コンテナのライフサイクル特性を測る)。
- task-A → task-B を**別々の `docker run --rm`** で回し、A の env 秘密/コンテナ内書込が B に残るかを見る。

## 実行内容と期待結果

| No | task-A(前タスク) | task-B(後タスク・新インスタンス) | 期待 | 結果 |
|---|---|---|:---:|---|
| k-1 | `-e LAB_TASK_SECRET=<乱数>` で起動 | `-e` **なし**で起動し `$LAB_TASK_SECRET` を読む | 🔒 空 | `__ABSENT__`(注入しなければ存在しない) |
| k-2 | `/home/node/scratch/prev-task.txt` に秘密を書いて `--rm` 破棄 | 新インスタンスで同パスを `cat` | 🔒 空 | `__ABSENT__`(コンテナ内書込は残らない) |

## なぜそうなるか

- **k-1(env は注入しなければ空)**: コンテナの env は `-e`/`containerEnv` で**明示注入したものだけ**存在する
  (04-h の再確認・タスク跨ぎ版)。前タスクに注入した秘密は、注入しない次インスタンスには**無い**。
- **k-2(コンテナ内書込は --rm で消える)**: bind mount **外**への書込はコンテナの書込レイヤに載り、`--rm` で
  コンテナごと破棄される。次インスタンスは同じイメージから**まっさら**に起動するので残らない。

→ これに対し「**役割で共有した長寿命コンテナ**」は、通過した全タスクの **env 秘密**(マスクされない=03-j/04-h)・
**コンテナ内書込**・**`~/.claude` 認証**(コンテナ内で読める=04-d)が**同居し続ける秘密の集積点**になる。
タスク A の claude がタスク B の注入秘密や生成物を読めてしまう。

## 運用時の留意事項

- **コスト対策は「共有」ではなく「役割テンプレート化 + タスク使い捨て」**で取る。コンテナ生成はイメージ層共有で速く、
  重いのは firewall/mount の**ポリシー構築**(=役割ごとに決まる。インスタンス数ではない)。役割イメージを固定して
  インスタンスを使い捨てれば、コストをほぼ変えずに fail-closed teardown を保てる。
- env で秘密を渡すなら**最小限のコンテナにだけ注入**し、注入した env は読めるので egress allowlist(04-d/l)と併せて締める。
- どうしてもプールするなら、タスク間分離は **fail-closed な機構**(別インスタンス、または per-task uid + タスク
  サブツリーのみの mount=[j](../j-per-task-mount-isolation/README.md))で。permission 規則(i)には負わせない。
